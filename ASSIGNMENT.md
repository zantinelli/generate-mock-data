# Overview
Build a small prototype that generates realistic security demo data + activity for a fictional company.

Most demo environments fail because the data is either too clean or obviously fake. I want to see how you’d fix that.

**At a minimum, your prototype should:**
- Create a believable baseline (users, access, resources, data, etc.)
- Generate activity over time (not just static data)
- Include a few security-relevant situations (e.g. over-permissioning, odd behavior, drift, etc.)
- Keep things internally consistent so it feels like a real environment, not random output
- Everything else is up to you — stack, structure, interface, level of depth.

## Constraints
- Keep it to ~4–6 hours
- Should run locally (no need to wire into real cloud systems)
- Don’t overbuild — one solid slice is better than a half-finished platform

## How the assignment will be reviewed
- How you scope the problem and what you choose not to do
- Structure and clarity (can someone else use/extend this?)
- Whether the output actually feels realistic/useful
- How you use AI/tools — speed is good, but I’m looking for control and judgment
- Tradeoffs and reasoning (quick notes are fine)

## Deliverable
**A GitHub repo with:**
- Working prototype
- Short README (how to run)
- Brief notes on decisions/tradeoffs
- A couple example outputs
